# Building `quant_engine_cpp` on Windows (MSVC)

Step-by-step guide for compiling the C++17 multithreaded Monte Carlo
engine into a Python extension module that `main.py` can import.

> **Verified path:** Windows 10/11 + Python 3.12 + **Visual Studio 2022**
> with the *"Desktop development with C++"* workload + **CMake 3.15+** +
> `pybind11` from `pip`.
>
> **What you'll get:** a single file
> `cpp_core\quant_engine_cpp.cp312-win_amd64.pyd` (or with whatever Python
> ABI tag you have) that `main.py` will import transparently.

---

## 0. Prerequisites (one-time)

1. **Visual Studio 2022 (Community is fine)** with the *"Desktop
   development with C++"* workload.
   - Make sure "MSVC v143 - VS 2022 C++ x64/x86 build tools" and
     "Windows 11 SDK" are selected in the installer.
   - Download: <https://visualstudio.microsoft.com/downloads/>
2. **CMake 3.15 or newer.** Either:
   - Install via the Visual Studio Installer ("CMake tools for Windows"),
     or
   - `winget install Kitware.CMake`, or
   - Download from <https://cmake.org/download/>.
3. **Python 3.9+** (you already have 3.12). Make sure your project
   virtual environment is activated before any of the commands below.

---

## 1. Install pybind11 in your project's virtual environment

```powershell
cd "D:\Folder dio\Porto\Options-Pricing"
pip install -r requirements.txt        # already adds pybind11>=2.11
```

You can verify the install with:

```powershell
python -c "import pybind11; print(pybind11.get_cmake_dir())"
```

That path is the one CMake uses under the hood.

---

## 2. Open a *Developer PowerShell for VS 2022* prompt

> **Important:** do *not* use a regular PowerShell. The Developer
> prompt pre-loads `cl.exe`, the MSVC compiler, into your `$PATH`.

You can launch it from the Windows Start menu:
**Start → Visual Studio 2022 → Developer PowerShell for VS 2022**.

In that prompt, navigate to the project:

```powershell
cd "D:\Folder dio\Porto\Options-Pricing\cpp_core"
```

---

## 3. Configure the project

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
```

If you're on an older Visual Studio, swap the generator:
- VS 2019 → `"Visual Studio 16 2019"`
- VS 2017 → `"Visual Studio 15 2017"`

This creates a `build\` directory with the Visual Studio solution. It
also auto-detects your `pybind11` install from the active Python
interpreter.

---

## 4. Build (Release)

```powershell
cmake --build build --config Release --parallel
```

A successful build prints something like:

```
quant_engine_cpp.vcxproj -> ...\cpp_core\build\Release\quant_engine_cpp.cp312-win_amd64.pyd
```

The actual file is then **copied** by CMake to the project root of
`cpp_core\`, so you'll also see:

```
cpp_core\quant_engine_cpp.cp312-win_amd64.pyd
```

> **Tip:** the ABI tag (`cp312-win_amd64` here) is automatically
> generated by pybind11 to match your Python version and platform.
> To see what your exact filename will be:
> ```powershell
> python -c "import sysconfig; print(sysconfig.get_config_var('EXT_SUFFIX'))"
> ```

---

## 5. Verify the import

From the project root (`D:\Folder dio\Porto\Options-Pricing`):

```powershell
python -c "import sys, pathlib; sys.path.insert(0, str(pathlib.Path('cpp_core'))); import quant_engine_cpp; print(quant_engine_cpp.MonteCarloPricerCpp)"
```

You should see something like:

```
<class 'quant_engine_cpp.MonteCarloPricerCpp'>
```

---

## 6. Run the demo

```powershell
cd "D:\Folder dio\Porto\Options-Pricing"
python main.py
```

In the static demo's "Prices" block, you'll now see **three** rows:

```
  BSM (analytical)  Call =  10.4506    Put =   5.5705
  MC   (Python)     Call =  10.4521 ... (SE=..., t=...ms)
  C++ MC (parallel) Call =  10.4498 ... (SE=..., t=...ms, threads=8)
```

If the `.pyd` isn't built yet, `main.py` silently falls back to the
two-row version.

## 7. Troubleshooting

### "Could not find a package configuration file provided by `pybind11`"

Your active venv doesn't have pybind11, or the CMake step ran in a
shell that used a *different* Python than the one with pybind11
installed. Run:

```powershell
python -m pip show pybind11
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DPython_EXECUTABLE=$(python -c "import sys; print(sys.executable)")
```

### "ImportError: DLL load failed while importing quant_engine_cpp"

The `.pyd` was built for a different Python (e.g. Debug build, or
a different ABI). Rebuild:

```powershell
cmake --build build --config Release --clean-first --parallel
```

Make sure you're calling the **same** `python.exe` that the build used.

### Wrong ABI tag / file not found

If `python -c "import quant_engine_cpp"` says `ModuleNotFoundError`,
check:

```powershell
ls cpp_core\*.pyd
```

The filename must end in the same ABI tag as your Python:

```powershell
python -c "import sysconfig; print(sysconfig.get_config_var('EXT_SUFFIX'))"
```

If they don't match, you're running a different Python than the one
that was active when you built — re-activate the correct venv and
re-run steps 3-4.

### Slow first build

The first compile takes ~30-60s; incremental rebuilds after editing
`bsm_engine.cpp` are usually < 5s.

### Want a Debug build (sanitizers, etc.)?

```powershell
cmake --build build --config Debug --parallel
```

Then in your Python session *before* importing:

```powershell
$env:PYTHONPATH = "cpp_core\build\Debug;$env:PYTHONPATH"
```

---

## 8. Cleaning up

```powershell
Remove-Item -Recurse -Force build
Remove-Item cpp_core\*.pyd
```

---

## 9. Optional: install the `.pyd` system-wide

If you'd rather not have `main.py` add `cpp_core\` to `sys.path` at
runtime, copy the compiled `.pyd` into your venv's `site-packages`:

```powershell
Copy-Item cpp_core\quant_engine_cpp.cp312-win_amd64.pyd `
          (python -c "import site; print(site.getsitepackages()[0])")
```

Then `import quant_engine_cpp` works from anywhere.
